# Contribuer au planificateur de trajets

Merci de votre intérêt pour ce projet. Il vise à rendre la planification de trajets à Montréal plus simple, transparente et utile, notamment pour comparer l’autopartage, le transport collectif, le vélo et les autres options de mobilité.

Le contenu a été préparé en partie avec l’aide de l’intelligence artificielle. Il peut donc contenir des imprécisions, des informations périmées ou des simplifications. **Les corrections, précisions et améliorations sont les bienvenues.**

Vous n’avez pas besoin d’être spécialiste de GitHub ni de programmer pour contribuer : une connexion GitHub et quelques minutes suffisent.

## Ce que vous pouvez signaler

Vous pouvez proposer une modification si vous repérez, par exemple :

- Un tarif, une règle ou une formule de calcul qui n’est plus à jour
- Une source officielle plus récente ou plus fiable
- Une erreur dans une explication, un exemple ou une recommandation
- Une information manquante sur les services de mobilité à Montréal
- Une formulation ambiguë ou difficile à comprendre
- Une amélioration du prompt, des données ou de la structure des fichiers

Quand c’est possible, ajoutez un lien vers la source officielle ou expliquez brièvement comment vous avez vérifié l’information. Cela aide à évaluer et intégrer la correction rapidement.

## La façon la plus simple : ouvrir une « Issue »

Une *Issue* est simplement une fiche pour signaler un problème ou suggérer une idée. C’est la meilleure option si vous ne souhaitez pas modifier les fichiers vous-même.

1. Créez gratuitement un compte ou connectez-vous à [GitHub](https://github.com).
2. Ouvrez l’onglet **Issues** du dépôt.
3. Cliquez sur **New issue**.
4. Donnez un titre clair, par exemple : `Tarif Communauto FLEX à mettre à jour`.
5. Décrivez ce qui devrait être corrigé et, si possible, ajoutez la source ou le lien pertinent.
6. Cliquez sur **Submit new issue**.

Vous pouvez aussi utiliser une Issue pour poser une question, signaler une donnée incertaine ou proposer une nouvelle fonctionnalité.

## Proposer directement une correction

Si vous êtes à l’aise de modifier un fichier Markdown, JSON ou autre fichier du dépôt, vous pouvez proposer la correction directement depuis GitHub, sans installer de logiciel.

1. Connectez-vous à GitHub et ouvrez le fichier à corriger.
2. Cliquez sur l’icône de crayon **Edit this file**.
3. Modifiez seulement ce qui est nécessaire.
4. En bas de la page, indiquez brièvement ce que vous avez changé dans le message de modification.
5. Choisissez **Create a new branch for this commit and start a pull request**.
6. Cliquez sur **Propose changes**.
7. Vérifiez le résumé de votre proposition, puis cliquez sur **Create pull request**.

Une *pull request* est une proposition de modification : elle ne change pas le contenu public immédiatement. Elle peut être relue, discutée et ajustée avant d’être intégrée.

> Si GitHub vous propose de créer une copie du dépôt (*fork*), acceptez : c’est normal. Votre proposition restera soumise à révision avant toute intégration au projet principal.

## Utiliser l’IA pour contribuer

Vous pouvez demander à un assistant IA qui a accès à GitHub de vous aider à :

- Repérer des tarifs, des dates, des liens ou des règles probablement périmés
- Comparer le contenu du dépôt avec une source officielle
- Rédiger une Issue claire à partir de vos observations
- Préparer une correction dans un fichier et une pull request
- Expliquer les changements techniques avant de les proposer

Exemple de demande :

> « Lis ce dépôt GitHub. Repère les informations de tarification qui semblent devoir être vérifiées, indique les fichiers concernés et prépare des propositions de correction avec leurs sources. Ne modifie rien sans me montrer la proposition. »

L’IA peut accélérer la vérification et la rédaction, mais elle peut elle aussi se tromper. Avant de soumettre une correction, vérifiez idéalement les éléments importants auprès des sources officielles.

## Bonnes pratiques

- Une proposition par sujet facilite la révision.
- Décrivez le problème et la correction proposée de façon concrète.
- Privilégiez les sources primaires : opérateurs de transport, organismes publics et documents officiels.
- Mentionnez la date de vérification lorsque l’information est susceptible de changer.
- Ne partagez pas de données personnelles, d’identifiants ou d’informations confidentielles.
- Gardez un ton constructif : l’objectif est d’améliorer collectivement la fiabilité de l’outil.

## Merci

Chaque signalement aide à rendre ce planificateur plus fiable et plus utile. Même une petite correction — un lien brisé, un tarif changé ou une phrase ambiguë — a de la valeur.
